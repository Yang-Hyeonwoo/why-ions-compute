Phase 2 · RC는 왜, 어떻게 작동하는가

이번 질문 — ESN 실습 코드를 어떻게 돌리고, NARMA10·NMSE·MC는 무엇을 재나?

왜 배우나 (내 소재 연구와의 연결) — 논문의 'NARMA10 NMSE 0.05'나 'MC 20' 같은 숫자는 내 소자 데이터로도 같은 방식으로 계산됩니다. 오늘 코드로 그 숫자가 어떻게 나오는지 보면, 내 소자 전류 시계열(상태 표)을 정규화하고 학습/검증/시험으로 나눠 NMSE와 MC를 재는 순서를 알게 됩니다.

오늘의 장면 (입력 → 내부 변화 → 출력) — 난수 입력 u(t) → NARMA10 정답 y(t) 만들기, 그리고 reservoir 200노드의 상태 → washout 구간 버리기 → 학습/검증/시험으로 나누기 → ridge readout 학습 → 시험 구간에서 NMSE와 MC 계산.

오늘 반드시 — NMSE는 평균 제곱 오차를 분산으로 나눈 값(평균값만 말하면 1)이고, MC는 지연별로 되살린 용량의 합이다. 둘 다 washout 뒤, 학습에 쓰지 않은 시험 데이터에서 재야 한다.

나중에 더 봐도 되는 것 — 터미널 명령의 옵션 세부, 전체 실행(1–2분)의 모든 출력 줄, delay tap 기준선의 구성 세부. 처음에는 --quick으로 base 줄 하나만 읽어도 됩니다.

다음으로 넘어가는 기준 — '오늘 반드시'를 내 말로 한두 문장 말할 수 있으면 됩니다. 나머지는 뒤의 Day에서 다시 나옵니다.

근거 표기와 Claude가 대조한 범위

근거 표기 [저자 연도, p.N]은 폴더 원문의 인쇄 쪽수이고, 누르면 참고문헌 항목으로 갑니다. 내가 읽은 논문(2026-10-23 기준): Readable papers1 전체와 Liang 2024(Nat. Electron.). Claude가 원문과 대조한 범위: Liang 2024는 p.194(식 1–2), p.200(MC·NARMA), p.201–202(비교·자원 조건); Stepney 2024는 3.2절(p.668–669), 7.1–7.2.2절(p.676–677, NMSE와 NARMA), 7.3.2절(p.679–680, MC); Singh 2026은 p.8(기준 비교의 조건)과 p.13만; Zhong 2022는 p.675, 677(정규화와 데이터 나누기)만. 미확인은 폴더에 없는 내용, 해석은 Claude의 해석, 가설은 검증이 필요한 것입니다. 실행 결과는 Claude의 컴퓨터(Python 3.12.10, numpy 2.5.4)에서 돌린 것이며, 2026-10-28과 10-29에 다시 돌려 본문의 숫자와 같은지 확인했습니다. 10-29에는 Python 3.9.10·numpy 2.0.2로도 돌렸는데, NMSE·MC 숫자는 모두 같았고 ESP 확인 줄의 아주 작은 값(e-16)과 ρ = 2.0 줄의 끝자리만 조금 달랐습니다.

1. 실습 준비: 터미널을 열고 코드를 돌리기까지

이 구간을 읽고 나면 study 폴더에서 터미널을 열고, Python과 numpy가 있는지 확인하고, python tools/esn.py --quick을 돌려 base 줄의 두 숫자를 "입력 → 상태 → 출력 → 오차"로 말하고, 입력 크기 하나만 바꿔 다시 돌린 결과와 비교할 수 있다. 전체 실행 python tools/esn.py도 돌릴 수 있다.

터미널이란. 마우스로 아이콘을 누르는 대신 글자로 컴퓨터에 명령하는 창입니다. 창에 PS C:\Users\…\study> 같은 줄이 보이는데, 이것을 프롬프트라고 부르고 "지금 이 폴더에 있으니 명령을 입력하라"는 뜻입니다. 명령을 치고 Enter를 누르면 실행되고, 결과가 아래에 글자로 나옵니다. Windows에서는 PowerShell이라는 터미널을 씁니다.

무엇을 볼지. 사진은 진짜 창의 모습이고, 아래 그림 1은 오늘 내 창에서 일어날 일을 순서대로 그린 것입니다. 그림 1(a)의 창에서는 번호 ①–⑤를 차례로 따라가고, (b)에서는 명령 한 줄이 빈칸으로 어떻게 조각나는지 보세요.

어디에 치나, 무엇을 치나. 프롬프트 끝(> 바로 뒤)에서 깜빡이는 짧은 막대(커서)가 글자가 들어갈 자리입니다. 창을 한 번 클릭해 두고 치면 됩니다. 이 자료의 회색 상자 안 글자가 칠 명령 전체이고, 창에 이미 보이는 PS …>는 컴퓨터가 써 둔 것이라 치지 않습니다. 직접 쳐도 되고, 회색 상자의 글자를 복사해 창에 붙여 넣어도 됩니다(Ctrl + V 또는 창 안에서 마우스 오른쪽 클릭). 명령 한 줄은 빈칸으로 나뉜 조각으로 되어 있습니다(그림 1(b)).

  • python: 실행할 프로그램. 사람이 쓴 .py 파일을 읽어 한 줄씩 실행해 주는 Python 프로그램입니다.
  • tools/esn.py: 실행할 파일. "지금 폴더(study) 안의 tools 폴더 안의 esn.py"라는 길, 곧 경로(path)이고, /는 폴더와 그 안의 것을 나누는 표시입니다. 이 경로는 지금 폴더에서 출발하므로, 지금 폴더가 study가 아니면 길이 맞지 않아 실행되지 않습니다.

첫 결과 한 줄: 방금 무슨 일이 일어났나. 빠른 확인의 결과 줄 가운데 base로 시작하는 줄 하나만 봅니다. Claude의 컴퓨터에서는 이렇게 나왔습니다(reservoir seed 1 한 벌).

이 한 줄 뒤에서 일어난 일을 "입력 → 상태 → 출력 → 오차"의 순서로 말하면 이렇습니다.

  1. 입력: 0~0.5 사이 무작위 숫자 4,000개를 한 단계에 하나씩 reservoir에 넣었다.

  4. 오차: 학습에 쓰지 않은 마지막 1,900단계에서, readout이 말한 값과 정답의 차이를 숫자 하나로 줄인 것이 0.0680이다. 0이면 완벽, 1이면 "정답의 평균값만 계속 말하는 것"과 같은 수준이다(정확한 정의는 2구간의 NMSE).

그다음 칸 17.23은 오차와 따로 잰 기억의 양입니다. 같은 reservoir에 서로 독립인 무작위 입력을 넣고 "몇 단계 전 입력을 지금 상태에서 되살릴 수 있나"를 재어 더한 값으로, 대략 지난 입력 17개쯤을 기억하는 양이라고 읽습니다(memory capacity, MC, 2구간). ± 0.0000은 reservoir를 seed 1 한 벌로만 만들어 흩어짐을 잴 수 없다는 뜻입니다(4구간).

이 숫자들은 컴퓨터 안에서 식을 계산한 소프트웨어 시뮬레이션이고, 이온 소자를 측정한 실험이 아닙니다. 노드 200개도 소자 200개가 아니라 식 속의 숫자 200개입니다(식은 이 구간 끝, 소자 실험으로 MC를 재는 일은 Day 23–24).

코드가 계산하는 식. Day 15–16에서 본 leak 있는 update식(Day 16 기초: leak)에 입력 크기 \(s_{in}\)과 치우침(bias) \(b\)를 더한 것입니다. Stepney가 소개한 leak 있는 ESN(식 3)을, 입력 첨자를 \(u(t+1)\)로 쓰는 저자별 변형으로 적었습니다. Stepney 2024, p.668

\[ x(t+1) = (1-a)\,x(t) + a\,\tanh\!\big(\rho\,W x(t) + s_{in}\,W_{in}\,u(t+1) + b\big), \qquad y(t) = W_{out}\cdot[1,\ u(t),\ x(t)] \]

기호는 모두 Day 13–18에서 본 것이고, 5구간에서 바꿀 'knob'가 여기 다 들어 있습니다.

  • \(x(t)\): 노드 \(N\)개(기본 200개)의 상태 목록(Day 13 기초: state update식).
  • \(W\)와 ρ: \(W\)는 노드끼리의 연결 세기를 적은 \(N \times N\) 난수 표이고, \(\rho W\)는 "가장 큰 배율(spectral radius)이 1이 되게 맞춘 표에 ρ를 곱해 배율을 정확히 ρ로 만든 것"입니다(Day 16 기초: spectral radius). 코드의 make_reservoir가 이 일을 합니다.
  • \(a\): leak. 매 단계 새로 계산한 값을 얼마나 섞을지 정하는 비율로, 1이면 매번 새 값으로 갈아 치우고 작을수록 옛 상태를 많이 남깁니다(Day 16 기초: leak).
  • \(W_{in}\): 입력 하나를 노드마다 다른 무게(−1~1 난수)로 나눠 주는 목록(Day 18 기초: input mask).
  • \(s_{in}\): 입력 크기. 입력에 곱하는 숫자 하나로, 3구간 '입력 스케일링'에서 설명합니다.
  • \(b\): 노드마다 다른 작은 치우침(−0.2~0.2 난수, Day 18 5구간의 "치우침").
  • \(W_{out}\): readout 가중치. \(W\), \(W_{in}\), \(b\)는 처음에 난수로 정한 뒤 고정하고, 학습하는 것은 \(W_{out}\)뿐입니다(Day 13 기초: ridge, 3구간).

입력 첨자가 \(u(t+1)\)인 것은 "새 상태 \(x(t+1)\)은 그 단계에 들어온 입력까지 받은 뒤의 상태"라는 약속입니다(Day 16 5구간에서 식을 번호 하나 당겨 적은 것과 같은 약속). 그래서 readout은 상수 1, 지금 입력 \(u(t)\), 그 입력까지 받은 상태 \(x(t)\)의 200개 값, 모두 202개의 숫자(특징)에 가중치를 곱해 더합니다.

NARMA10 과제

Day 19–20에서 식만 미리 보았던 과제입니다(Day 19 1구간). 여기서 항마다의 뜻을 풉니다.

무엇을 시키나. 1구간의 "출력" 단계에서 readout이 맞히려 한 "정해진 규칙"이 이것입니다. 입력 \(u\)를 받아, 정해진 규칙(NARMA10 계)이 같은 입력에 대해 내놓을 출력 \(y\)를 흉내 내는 과제입니다. 실행 장면으로는 이렇습니다. reservoir에는 매 단계 \(u\)만 넣고 \(y\)는 보여 주지 않습니다. readout이 매 단계 상태를 보고 \(y(t)\)의 값을 말하도록 학습 구간에서 가중치를 맞추고, 시험 구간에서 readout이 말한 값(예측)을 진짜 \(y\)(정답)와 비교해 채점합니다. Stepney는 이것을 "흉내(imitation) 과제"로 분류하고, RC 문헌에서 아마 가장 흔한 벤치마크라고 씁니다. Stepney 2024, p.676 Liang도 NARMA를 비선형 계 근사와 기억을 동시에 시험하는 널리 받아들여진 벤치마크로 소개합니다. Liang 2024, p.200

규칙. 입력 \(u\)는 0~0.5 사이 균등 난수(그 범위의 어느 값이나 나올 가능성이 같은 무작위 수)이고,

\[ y(t+1) = 0.3\,y(t) + 0.05\,y(t)\sum_{i=0}^{9} y(t-i) + 1.5\,u(t-9)\,u(t) + 0.1 \]

(Atiya & Parlos 2000의 매개변수 (0.3, 0.05, 1.5, 0.1)와 입력 범위 0.5 Stepney 2024, p.676). 항마다 하는 일:

  • \(0.3\,y(t)\): 바로 전 출력의 30%가 남는다(남는 비율 \(d\) = 0.3짜리 흐려지는 기억, Day 15 기초: fading memory). 지금 출력 \(y(t)\)로 다음 출력 \(y(t+1)\)을 만드는 식이라, 맞히려면 \(y\)의 과거도 알아야 하는데 reservoir는 \(y\)를 보지 못하므로 결국 지난 입력들에서 그것을 다시 만들어 내야 합니다.
  • \(0.05\,y(t)\sum y\): 지금 출력과 최근 10개 출력의 합의 곱(2차 비선형 + 10단계 기억).
  • \(1.5\,u(t-9)\,u(t)\): 지금 입력과 9단계 전 입력의 곱(2차 비선형 + 기억). 이 곱이 들어가는 출력은 \(y(t+1)\)이므로, 출력 시점에서 보면 1단계 전과 10단계 전 입력의 곱입니다. Day 17–18의 지연 XOR(두 입력이 서로 다를 때만 1이라 곱 같은 비선형이 필요한 과제, Day 17 기초: XOR)을 10단계로 늘린 것과 같은 성격입니다.
  • \(0.1\): 상수.

Stepney는 이 식의 (2차) 비선형이 출력끼리의 곱(\(y(t)\,y(t-i)\)) 항과 입력끼리의 곱(\(u(t-9)\,u(t)\)) 항에서 오고, 이전 10단계의 기억이 필요하다고 정리합니다. Stepney 2024, p.676 Stepney는 출력을 \(x\), 과제의 길이를 \(N\)으로 적는다. 이 교재에서 \(x\)는 reservoir 상태, \(N\)은 노드 수라서 Day 19–20처럼 \(y\)와 10으로 바꿔 적었다.

한 걸음 손 계산. 최근 출력 10개가 모두 0.3이고(\(y(t) = 0.3\), 합 3.0), \(u(t-9) = 0.4\), \(u(t) = 0.2\)라면

  1. \(0.3 \times 0.3 = 0.09\)
  2. \(0.05 \times 0.3 \times 3.0 = 0.045\)
  3. \(1.5 \times 0.4 \times 0.2 = 0.12\)
  4. 더하면 \(0.09 + 0.045 + 0.12 + 0.1 = 0.355\)

주의 둘. (1) 이 식은 가끔 값이 폭주합니다. Stepney는 표준 NARMA10 설정도 가끔 발산한다고 적고 Stepney 2024, p.676, tools/esn.py는 값이 10을 넘으면 데이터 seed를 바꿔 다시 만듭니다(우리 데이터는 seed 7에서 문제없이 만들어졌고, 출력 범위는 0–0.778). (2) 문헌마다 매개변수와 입력 범위가 달라 숫자를 바로 비교하기 어렵고, 무엇을 재는지도 정확하지 않아 조심해서 써야 한다고 Stepney는 경고합니다. Stepney 2024, p.677 그래서 오늘은 NARMA10과 함께 MC를 봅니다.

읽는 법. 아래 원문 그림은 위 규칙으로 만든 \(y\)가 시간에 따라 어떻게 생겼는지 보여 줍니다. 가로축은 시간 단계, 세로축은 출력 값이고, 위 칸의 파란 곡선만 보면 됩니다. 이것이 오늘의 NARMA10(Atiya & Parlos 매개변수, 입력 범위 0.5)이고, 세로축 값이 대략 0.15–0.75 사이를 오르내립니다. 같은 입력인데 입력 범위만 0.2로 줄인 주황 곡선은 0.2 근처에 납작하게 붙어 있습니다. "NARMA10"이라는 같은 이름이라도 설정이 다르면 전혀 다른 신호라는 것을 확인하세요.

오차 척도 NMSE (정규화 평균 제곱 오차)

Day 19–20에서 이미 계산한 것. Day 19–20의 용량 \(C = 1 - \langle(f-\hat f)^2\rangle/\mathrm{Var}(f)\)에서 1에서 빼는 부분, 곧 "오차 제곱의 평균 ÷ 정답의 분산"이 여기서 부르는 NMSE입니다(Day 19 기초: 목표 하나의 용량). 평균 \(\langle\cdot\rangle\), 분산, 표준편차도 거기서 숫자 넷으로 계산했습니다. 여기서는 이름과 실습에서의 쓰임을 붙입니다.

왜 필요한가. "오차 0.02"라는 말은 정답이 0.4 근처를 오가는지 400 근처를 오가는지 모르면 뜻이 없습니다. 정답이 원래 얼마나 흔들리는지로 나눠 주면 단위와 크기에 상관없이 비교할 수 있습니다.

정의. 정답은 NARMA10이 만든 진짜 \(y\), 예측은 readout이 말한 값입니다. 시험 구간의 시간 단계마다 둘의 차이(오차)를 구해

\[ \text{NMSE} = \frac{\text{평균}\big[(\text{정답} - \text{예측})^2\big]}{\text{정답의 분산}} \]

분자의 "평균"은 Day 19–20의 \(\langle \cdot \rangle\)와 같은 뜻입니다(시간 단계마다 계산해 단계 수 \(n\)으로 나눔).

분산은 "정답이 자기 평균에서 얼마나 흩어져 있나"(평균에서 뺀 값의 제곱의 평균)입니다. 여기서는 분자의 "평균"과 맞춰 개수 \(n\)으로 나눕니다(코드의 np.var도 \(n\)으로 나눔). 표본 분산은 \(n-1\)로 나누지만, 시험 구간이 1,900단계라 차이는 무시할 만합니다(분산을 더 깊게: Day 23 기초: 분산·상관²). Stepney의 식 15와 같고, 예측을 늘 정답의 평균값으로 내면 NMSE = 1이라고 적습니다. Stepney 2024, p.676 그래서 0이면 완벽, 1이면 "아무것도 모르고 평균만 말하는 것"과 같습니다. 문헌에서 가장 흔한 것은 그 제곱근 NRMSE입니다. Stepney 2024, p.676 Day 19–20의 용량 \(C\)는 \(1 - \text{NMSE}\)였습니다.

작은 숫자로. 정답 (0.4, 0.5, 0.3, 0.6), 예측 (0.42, 0.47, 0.33, 0.58).

  1. 오차: (0.02, −0.03, 0.03, −0.02), 제곱 평균 \(= (0.0004 + 0.0009 + 0.0009 + 0.0004)/4 = 0.00065\).
  2. 정답의 평균 0.45, 평균에서 뺀 값 (−0.05, 0.05, −0.15, 0.15), 제곱 평균(분산) \(= (0.0025 + 0.0025 + 0.0225 + 0.0225)/4 = 0.0125\).
  3. NMSE \(= 0.00065/0.0125 = 0.052\). NRMSE \(= \sqrt{0.052} = 0.23\).
  4. 확인: 예측을 모두 정답의 평균 0.45로 내면 오차는 (−0.05, 0.05, −0.15, 0.15)로 2단계의 "평균에서 뺀 값"과 똑같고, 그래서 제곱 평균이 분산과 같은 0.0125라 NMSE \(= 0.0125/0.0125 = 1\)입니다. "평균만 말하면 1"이 이렇게 나옵니다.

1구간의 base 줄에서 본 0.0680이 바로 이 NMSE(seed 1 한 벌의 값)이고, 전체 실행의 seed 3개 평균은 0.053입니다. NMSE는 오차 제곱의 평균을 정답의 분산과 견준 비율이라, 0.068은 "평균만 말하는 예측"(NMSE 1)이 내는 오차 제곱의 약 7%라는 뜻입니다. NMSE 0.05가 눈으로 어느 정도인지 그림 3에서 보세요. (a)의 검정이 정답, 파란 점선이 예측이고, (b)의 빨간 선은 둘의 차이입니다.

여기까지: NARMA10 한 걸음(0.355)을 손으로 계산하고, NMSE를 숫자 넷 예(0.00065 ÷ 0.0125 = 0.052)로 계산해 "0이면 완벽, 1이면 평균만 말하는 것"을 말할 수 있다. 다음: 오차와 따로, 기억만 재는 MC.

memory capacity(MC) 측정 방법

무엇을 재나. "이 reservoir는 \(k\)단계 전 입력을 지금 상태에서 얼마나 되살리나"를 \(k\) = 1, 2, 3, …에 대해 재서 더한 것입니다. Day 16 5구간의 "memory budget"과 Day 19–20의 "차수 1 용량"이 바로 이것입니다.

순서. Liang 2024, p.200 Stepney 2024, p.679

  1. 입력으로 서로 독립인 난수를 넣는다(tools/esn.py는 −1~1 균등 난수). 독립이어야 지금 입력에서 과거 입력을 "추측"할 단서가 없고, 상태에 남은 흔적만 잴 수 있다.
  2. 지연 \(k\)마다 목표를 "\(k\)단계 전 입력 \(u(t-k)\)"로 두고 readout을 학습한다.
  3. 시험 구간에서 목표와 readout 출력의 상관계수(두 숫자 열이 함께 오르내리는 정도, −1~1, Day 16 5구간)를 제곱한다: \(MC_k\)(0~1). Day 19–20의 용량 \(C\) = 1 − NMSE와 시험 구간에서 거의 같은 양입니다(Day 19 기초 단계 5).
  4. 모두 더한다: \(MC = \sum_k MC_k\). 코드는 \(k\) = 1–200을 더한다.

작은 숫자로. \(MC_k\)가 \(k\) = 1–7에서 1.0, 0.99, 0.95, 0.8, 0.5, 0.2, 0.05이고 그 뒤는 0이라면 \(MC = 4.49\)입니다. "약 4.5개의 지난 입력을 온전히 기억하는 것과 같은 양"이라고 읽습니다. 1구간의 17.23(seed 1 한 벌, seed 3개 평균은 17.92)도 같은 방식으로 더한 합이고, 입력 크기 0.1에서 28.80으로 늘었던 것은 그림 4의 주황 곡선이 더 오래 버티는 것으로 보입니다.

상한과 주의. Stepney는 Jaeger(2002)가 독립 난수 입력에서 \(MC \le N\)(노드 수)임을 보였다고 씁니다. Stepney 2024, p.679 그리고 \(k\)가 클수록 \(MC_k\)는 작고 잡음에 가까워지므로 실제로는 어디서 끊는다고 적습니다. Stepney 2024, p.679 Singh 2026은 합계 하나가 아니라 \(MC_k\) 대 \(k\)의 분포 전체를 함께 보고하라고 권하는데, 합이 비슷해도 기억이 닿는 범위가 다를 수 있기 때문입니다. Singh 2026, p.13 그림 4가 그 분포입니다.

그림 4를 읽는 법. 가로축은 지연 \(k\)(몇 단계 전 입력인가), 세로축은 \(MC_k\)(0~1)이고, 곡선 아래 넓이가 MC입니다. 곡선 넷은 5구간에서 바꿔 볼 조건들이라 지금은 파란 선(기본 설정)만 보세요. 파란 선은 \(k\) = 19에서 처음 0.5 아래로 떨어집니다. 이것이 "기억이 닿는 범위"의 대략적인 끝이고, NARMA10이 요구하는 10단계(가로축 10)보다 깁니다. 세로 점선은 바로 아래에서 설명할 기준선이고, 주황·회색·빨강 곡선은 5구간의 knob 2·4·5에서 다시 봅니다.

delay tap + 선형 회귀 기준선

무엇인가. reservoir를 빼고, 지난 입력들을 그대로 저장해 readout에 넣는 방법입니다. 탭 \(k\)개면 특징은 \([1,\ u(t),\ u(t-1),\ \dots,\ u(t-k+1)]\), 즉 \(k + 1\)개이고, 여기에 reservoir와 같은 ridge readout(Day 13 기초)을 그대로 씁니다. "탭(tap)"은 수도관(지연선)의 여러 자리에서 물을 뽑는 꼭지처럼, 지연된 신호를 자리마다 뽑아 쓴다는 뜻입니다.

2차 판. 탭들끼리의 곱(제곱 포함)까지 특징으로 넣으면 2차 비선형도 readout이 직접 다룹니다. 특징 수는 \(1 + k + k(k+1)/2\): 탭 10개면 \(1 + 10 + 55 = 66\), 탭 20개면 \(1 + 20 + 210 = 231\)입니다. 탭 3개로 한 시각을 적어 보면, \(u(t), u(t-1), u(t-2)\) = 0.2, 0.4, 0.1일 때 선형 판의 특징은 [1, 0.2, 0.4, 0.1] (4개 = 3 + 1), 2차 판은 여기에 제곱 셋(0.04, 0.16, 0.01)과 서로 다른 둘의 곱 셋(0.2 × 0.4 = 0.08, 0.2 × 0.1 = 0.02, 0.4 × 0.1 = 0.04)을 더해 10개(\(1 + 3 + 3 \times 4/2\))입니다. 곱의 개수 \(k(k+1)/2\)는 "탭 \(k\)개에서 둘을 고르는 방법 + 제곱 \(k\)개"입니다.

왜 필요한가. Day 10에서 말한 기준선입니다. 기억을 저장으로 얻는 가장 정직한 방법(Day 15 1구간)이고, reservoir가 이보다 낫지 않다면 "reservoir의 동역학이 계산에 기여했다"고 말할 수 없습니다. Singh 2026은 물리 reservoir의 기여를 같은 입력 부호화, 같은 데이터 나누기, 같은 정규화, 가능하면 같은 특징 수와 같은 readout을 쓴 기준 사례와 비교하라고 씁니다. Singh 2026, p.8

확인용 계산. 탭 20개는 \(u(t-1)\)부터 \(u(t-19)\)까지를 그대로 들고 있으므로, MC를 재면 \(k\) = 1–19에서 1, 그 뒤는 0이라 약 19가 나와야 합니다(그림 4의 세로 점선). 실제 출력은 19.06(나머지 0.06은 유한한 데이터에서 생기는 우연한 상관)입니다. 탭 10개는 9.08, 50개는 49.03. 내 출력에서도 이 숫자가 나오면 MC 계산이 제대로 돌아간 것입니다.

탭 10개 기준선은 \(u(t), u(t-1), \dots, u(t-9)\)를 듭니다. NARMA10 식의 \(t\)를 한 단계 당겨 적으면 \(y(t) = 0.3\,y(t-1) + \cdots + 1.5\,u(t-10)\,u(t-1) + 0.1\)이라, 지금 정답 \(y(t)\)를 맞히려면 \(u(t-1)\)과 \(u(t-10)\)의 곱이 필요합니다. 탭 10개의 NARMA10 성적은 좋을까요, 나쁠까요? 출력에서 확인하세요.

  • NARMA10: 2차 곱 + 10단계 기억을 요구하는 흉내 과제 Stepney 2024, p.676 Liang 2024, p.200. 설정이 다르면 숫자 비교 불가 Stepney 2024, p.677. 손 계산 예 0.355.
  • NMSE = 평균 제곱 오차 ÷ 정답의 분산. 평균만 말하면 1 Stepney 2024, p.676. 예: 0.00065/0.0125 = 0.052.
  • MC = 독립 난수 입력의 \(k\)단계 전 값을 되살리는 corr²의 합, \(\le N\) Stepney 2024, p.679. 분포 전체를 보라 Singh 2026, p.13.
  • delay tap 기준선: 특징 \(k+1\)개(2차는 \(1 + k + k(k+1)/2\)). 탭 20개의 MC ≈ 19가 계산 확인용이다. 같은 특징 수로 비교한다 Singh 2026, p.8.

3. 데이터를 다루는 기초: 정규화·입력 크기·washout·나누기

이 구간을 읽고 나면 정규화, 입력 스케일링, washout, 학습/검증/시험 나누기가 각각 무엇을 막는지 말하고, tools/esn.py의 s_in, WASHOUT, T_TRAIN, LAMBDAS가 그 어느 것에 해당하는지 짚을 수 있다.

전처리 기초: 정규화·입력 스케일링·washout·훈련/시험 나누기

넷은 각각 다른 문제를 막습니다. 정규화는 신호마다 크기가 달라 생기는 혼란을, 입력 스케일링은 노드가 너무 곧게만 움직이거나 너무 포화하는 것을, washout은 처음 상태의 흔적을, 나누기는 외운 것을 실력으로 착각하는 것을 막습니다. 넷 가운데 washout과 나누기는 Day 11–16에서 이미 본 것이라 짧게 다시 말하고 링크를 겁니다.

정규화(normalization). 원래 신호의 단위와 크기를 정해진 범위로 맞추는 일입니다. 예: 심전도 값 0.2, 0.8, 1.4 mV를 −1~1로 맞추려면 "(값 − 최솟값) ÷ (최댓값 − 최솟값) × 2 − 1"을 계산합니다. 0.2 → −1, 0.8 → 0, 1.4 → +1. Zhong 2022는 박동 하나하나를 진폭이 [−1, 1]이 되게 정규화했습니다. Zhong 2022, p.675 왜 하나? 사람마다, 측정마다 크기가 다른 신호를 같은 reservoir에 넣어도 같은 운전 영역(아래 입력 스케일링)에서 움직이게 하기 위해서입니다. 해석 주의: 최솟값·최댓값(또는 평균·표준편차)은 학습 데이터에서만 구해야 합니다. 시험 데이터로 구하면 시험 데이터의 정보가 학습에 새어 들어갑니다. 해석

입력 스케일링(input scaling). 정규화한 입력에 숫자 하나(\(s_{in}\))를 곱해 reservoir에 들어가는 세기를 정합니다. Day 17–20에서 보았듯(Day 20 기초: 상충) 이 숫자가 노드가 \(\tanh\)의 직선 구간에서 움직일지(거의 선형, 잡음에 묻힘) 휘는 구간까지 갈지(비선형, 기억 감소)를 정합니다. Stepney는 입력이 reservoir 동역학을 흔들 만큼 크되 포화시키지 않을 만큼 작게 맞추고, spectral radius와 함께 조절하라고 씁니다. Stepney 2024, p.668 Liang도 time multiplexing 뒤에 치우침과 크기 조절을 더해 최적의 입력 범위를 찾을 수 있다고 적습니다. Liang 2024, p.198 tools/esn.py에서는 s_in(기본 0.5)이 이것이고, NARMA10 입력(0~0.5)은 따로 정규화하지 않고 그대로 \(s_{in}\)을 곱합니다.

washout. 처음 몇 단계는 처음 상태(코드에서는 모두 0)의 흔적이 남아 있으므로 학습·평가에서 버립니다(Day 12 3-1: washout, Day 15 3구간: washout과 ESP). 코드 맨 위의 설정값 WASHOUT = 100이 이것입니다.

훈련/검증/시험 나누기. 남은 데이터를 시간 순서대로 셋으로 나눕니다. 먼저 그림 5에서 칸 넷의 순서와 길이(단계 수에 비례)를 보세요.

그림의 순서를 글로 따라가면 이렇습니다.

  1. 처음 100단계(washout)를 버린다.
  2. 다음 1,500단계(학습)로, ridge의 \(\lambda\)(가중치가 지나치게 커지는 것을 벌하는 세기, Day 13 기초: ridge의 λ) 후보 LAMBDAS(10⁻⁹, 10⁻⁷, 10⁻⁵, 10⁻³, 10⁻¹) 다섯 개마다 readout을 푼다.
  3. 다음 500단계(검증)에서 다섯 readout의 NMSE를 재어 가장 작은 \(\lambda\) 하나를 고른다.
  4. 고른 \(\lambda\)로 학습 + 검증 2,000단계 전체에서 readout을 다시 푼다. 출력 첫 줄의 train 2000이 이 2,000단계이고, 코드의 설정값 T_TRAIN = 2000입니다.
  5. 마지막 1,900단계(시험)로 성적을 한 번 잰다. 이렇게 \(\lambda\)는 검증으로 고르고 성적은 시험으로 재는 것이 Day 13–14에서 본 순서입니다(Day 13 4-5).

시계열은 섞지 않고 시간 순서대로 나눕니다. 상태가 과거를 담고 있어 섞으면 학습과 시험이 서로의 이웃 시점을 공유하게 되고, 실제 사용(앞으로 올 데이터)과도 다르기 때문입니다. 해석

소자 논문의 예. Zhong 2022는 박동 10,000개 중 무작위 1,000개로 학습하고 나머지 9,000개로 시험했고 Zhong 2022, p.675, 손동작은 600개 학습, 300개 시험으로 나눴습니다. Zhong 2022, p.677 여기서 나눈 단위는 시간 단계가 아니라 박동·동작 하나하나입니다.

MC는 따로 나눕니다. MC는 따로 만든 −1~1 난수 입력으로 재며, 지연 200까지의 목표 \(u(t-200)\)을 만들 수 있도록 처음 200단계를 버리고, 다음 2,000단계로 학습, 나머지 1,800단계를 시험으로 씁니다(\(\lambda\)는 10⁻⁷로 고정, 코드의 memory_capacity).

"학습 데이터에서 잘 맞으면 된다" — Day 10과 Day 13–14에서 본 대로, 학습 데이터 오차는 readout이 외우기만 해도 줄어듭니다. 출력의 모든 NMSE와 MC는 시험 구간에서 잰 값입니다. 그리고 \(\lambda\)도 시험 구간이 아니라 검증 구간으로 골랐습니다. 시험 구간을 보고 설정을 고르면 시험 구간도 학습에 쓴 셈이 됩니다.

  • 정규화: 크기를 정해진 범위로(예: [−1, 1] Zhong 2022, p.675). 통계는 학습 데이터에서만 해석.
  • 입력 스케일링 \(s_{in}\): 운전 영역을 정한다. 흔들 만큼 크게, 포화시키지 않게 Stepney 2024, p.668.
  • washout 100단계 → 학습 1,500(λ 후보마다 풀기) → 검증 500(λ 고르기) → 고른 λ로 2,000단계에서 다시 풀기(train 2000) → 시험 1,900. 시간 순서대로 나눈다.
